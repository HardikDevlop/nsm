The module is organized as a flat package of cooperating services with a clear dependency direction: configuration flows outward from `config.py`, low-level primitives (`ping_engine`, `parser`, `os_detector`, `utils`) are consumed by higher-level services, and orchestration sits at the top. `main.py` provides the CLI entry point that constructs a `DiscoveryManager` and runs a single pass, while `app.py` exposes an equivalent Flask HTTP API over `/api/discovery/run`, `/api/inventory`, `/api/discovery/summary`, and `/api/discovery/modules`. `DiscoveryManager` is the central orchestrator: it instantiates all discovery modules (imported from the sibling `discovery_modules.*` package), chains them in a fixed pipeline (IP → ICMP → TCP/DNS/ARP/HTTP/SNMP/WMI/SSH enrichment → profiling → inventory store → monitoring summary), and returns a frozen `DiscoveryRun` dataclass. Enrichment is parallelized via `ThreadPoolExecutor` using chunked iteration driven by `DISCOVERY_CHUNK_SIZE`. Persistence is handled by `InventoryService`, which normalizes profiled records into a stable schema and delegates to the thread-safe `Inventory` class backed by JSON on disk. Supporting services include `DeviceProfilingService` (device classification from open ports and probe results), `MonitoringServices` (aggregate stats and per-device health), `ScanState` (deduplication and retry tracking), `SchedulerLoop` (daemon-threaded periodic execution), and `logger` (thread-safe file+console logging). Cross-cutting concerns like IP generation, validation, timing, and JSON I/O live in `utils.py`.
